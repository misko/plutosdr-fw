# Issue 119: Fast Lock attestation

## Plan and reviewed scope

Review [issue 119](https://github.com/misko/plutosdr-fw/issues/119), preserve the
existing UAPI, implement fail-closed recall checks, test deterministic failures,
then qualify and deploy to USB radio `1040007c4a94000211000b009186843ef2` at
`192.168.1.18`. Use its existing v0.54 RC1 firmware baseline (firmware
`0ffdfe964247`, Linux `9be23c72ebf3`) to avoid unrelated release changes.

Hardware disproved the proposed direct-register frequency oracle. RX registers
0x231–0x235 and the RX nibble of 0x005 retain the last conventional tune during
Fast Lock. A TX2 DDS tone at 959.6875 MHz + 250 kHz appears on both loopback
receivers only when profile 0 is selected; it disappears on the three other
profiles, while the conventional register values remain fixed at 1709.6875 MHz.
The operator confirmed TX2 feeds both receivers through an attenuator and tee.
The probe used TX2 hardware gain -40 dB and DDS scale 0.1; TX1 stayed muted.

The user explicitly selected the revised approach: preserve Fast Lock and harden
selection, lock, and counter checks. Independent physical frequency attestation
is not claimed. The ordinary-register comparison requested in the issue would
reject working recalls on this radio and is therefore not deployed.

## Implementation

- Read the actual Fast Lock selector and mode bits; reject wrong profiles,
  disabled mode and external pin selection.
- Decode the selected profile frequency with checked SPI reads and preserve the
  existing two-Hz tolerance. Rename the helper to identify its profile source.
- Poll RX VCO_LOCK with a 2 ms deadline; propagate negative SPI errors before
  inspecting bits and reject a lock observation after the deadline.
- Sample counter_after only after lock, selector, frequency and post-recall CRC
  reads succeed. Keep the existing CRC/ALC update behavior and ABI layout.
- Invalidate scan configuration and restore the previous RX LO on failures.
  Check conventional RFPLL registers, Fast Lock exit and PLL lock during
  restoration, where conventional-register decoding is valid.
- Propagate Fast Lock preparation and ALC access errors; attempt all exit writes
  and retain restoration state if exit fails.
- Leave the iiOD same-target no-recall fast path unchanged: it still has a zero
  transition interval and does not imply a fresh hardware attestation.

## Validation and deployment

Local evidence is
kept in the ignored `evidence/` directory; the kernel candidate and package
manifest are under `build/candidate/`. The package reuses the verified release's
rootfs, FPGA and device trees, replacing the kernel and firmware identity only.


### Completed results

- Kernel commit: `74973ff563fe6c5f95591da40e3fb89c52657ee7` on
  `codex/issue-119`. The patch also applies cleanly to the local v0.59 kernel
  `a008394055c7`; only the v0.54-based candidate was hardware-qualified here.
- All 46 deterministic production-function fault tests pass, including every
  preparation/exit write position, ALC errors, six frequency-word reads,
  selector errors, lock read errors/deadline, mismatch, CRC failures, restoration
  failure, and success ordering. Kernel zImage cross-compilation passed.
- The kernel configuration is byte-for-byte identical to the configuration
  extracted from the deployed baseline kernel. Of 767 rootfs archive entries,
  only `opt/VERSIONS` changed. iiOD retains its release SHA-256
  `c932714528a168c88222593e1e678c93983ae707b12ec5fb0d0d7cbc519888f2`.
- RAM qualification: 72 successful API recalls across four profiles, including
  repeated-profile recalls, with 8/8 tone/channel acceptance cells passing.
  Minimum matching-tone contrast over every nonmatching profile was 40.4 dB.
  Source brackets were 6,243–7,393 ticks at 2.5 MS/s. Configuration restoration
  passed with no errors.
- Post-persistent qualification: another 72 recalls and 8/8 tone/channel cells
  passed, with brackets of 5,895–8,226 ticks. Configuration restoration passed.
- Normal RX-only adaptive scanning at 10 MS/s passed for 10 seconds in each
  boot: 73 RAM visits and 74 persistent visits, with zero invalid, skipped,
  cancelled or error visits. IQ geometry, counter continuity, timing query,
  anchor coverage and restoration checks all passed.
- Final ordinary libiio access captured 32,768 bytes. RX LO was restored to
  2.4 GHz, Fast Lock disabled, VCO_LOCK asserted, both TX gains -80 dB and all
  eight DDS scales zero.

Committed summaries, raw recall receipts, image checksums and final health are
in `reports/issue119/`. Detailed local logs, snapshots and private rollback files
remain in ignored `evidence/`. The initial standalone tone probe had a buffer
cleanup error, and the first API tone analysis included counter-prefix words;
those runs are retained as diagnostics. The final two campaigns used corrected
buffer lifetime, IQ-only windows, complete pre-write snapshots and ordered
restoration, and passed without restoration errors.

The original issue's stronger guarantee remains unavailable: correct profile
SRAM plus an asserted lock and matching selector do not independently prove
physical frequency on every production visit. The user explicitly chose this
Fast Lock-preserving scope after RF testing disproved the suggested direct-SPI
oracle. The tone campaign is separate end-to-end qualification, not a new wire
field or an absolute-frequency accuracy certification.

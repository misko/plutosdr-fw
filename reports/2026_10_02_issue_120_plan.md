# Issue #120: native 1.25 MS/s adaptive capture

**Completed:** fixed, tested, and persistently deployed over PPU LAN to `.15`.
Installed firmware: `v0.60-plutoplus-spf-adaptive-native-1p25-rc1`.
For low-rate operation, use v3, RX mask 3, 120 ms dwell, manual 40 dB gain,
and **500,000 samples per transport block**. The installed image delivered
75/75 complete visits at this geometry with zero skips/errors, then an ordinary
dual-RX capture succeeded. The 2.5 MS/s regression control also passed.

Target: `192.168.1.15`, serial `104000b29905000e17000800065934759d`, over PPU's physical LAN transport. Read-only discovery reports v0.59. All hardware capture is RX-only, with a cumulative 30-minute attempt budget and ten-second initial cells. Production host policy remains unchanged.

## Diagnosis and design

The issue's v2 failures at both 1.25 and 2.5 MS/s do not establish a low-rate hardware limitation. Match frequency targets, dwell, gain, buffers and duration across protocols before drawing that conclusion.

Source inspection found that the scheduler records gain for every protocol, while the visit encoder rejects gain observations outside v3. `READSCAN` also aborts its parser on errors without returning a negative response. Reproduce this chain and add regression coverage before changing it.

1. Preserve existing protocol versions and bit assignments. Add bit 8 for native 1.25 MS/s to v3's explicit rate mask. The existing active/quiet dwell semantics give fixed 120 ms visits when configured with dwell=120. Require exact rate readback and negotiated capability before capture.
2. Keep gain observations confined to v3. Older records retain zero reserved gain bytes. Exercise complete producer-to-wire visits, not only standalone encoders.
3. Return a negative READSCAN response for setup/start/encoding failures and retain underlying capture failure causes. Bound stalled capture progress and verify cancellation, restoration and subsequent ordinary capture.
4. Extend PPU's negotiated rate map and qualification harness. Retain native IQ and counter/UTC evidence; each complete low-rate visit must contain 150,000 samples per receiver and 1,200,000 bytes. Do not change published Leo archive contracts or enable its 25/75 production selection policy.

## Confirmed root cause and implemented changes

The matched v2 baseline at both rates timed out before its first record. The
matched 2.5 MS/s v3 baseline delivered 74 visits. The regression test reproduced
the v2 encoding failure by feeding a genuine session a gain observation before
encoding its completed visit. The scheduler had started doing that for every
protocol, but only v3 permits those fields. `READSCAN` discarded the resulting
negative error instead of sending a response, leaving the client waiting.

The fix preserves zero gain fields for legacy protocols, samples gain only for
v3, and writes negative READSCAN errors to the wire. Producer failures now retain
their original errno rather than becoming cancellation. A monotonic DMA-progress
deadline covers missing first blocks and incomplete final blocks: two block
periods plus two seconds, with a five-second minimum. Restoration failure also
returns an error rather than waiting for an impossible restored terminal.

Native 1.25 MS/s uses the new bit 8 (`0x100`) in v3's rate mask. The new advertised
mask is `0x171`; every existing bit retains its meaning, and old PPU main accepts
the expanded capabilities. Setup/readback and visit metadata remain explicitly
native 1,250,000 S/s. A 120 ms visit contains 150,000 samples per receiver and
1,200,000 bytes of interleaved dual-RX CI16. No software decimation is used.

## Hardware results

All cells used the same four targets from the issue, dual RX, 120 ms dwell,
manual 40 dB gain, and ten-second requested capture duration. The default
transport block was 1,000,000 samples; the final low-rate geometry uses 500,000.

| Cell | Result |
| --- | --- |
| Baseline v2, 1.25 and 2.5 MS/s | First-record timeouts; no visits; settings restored |
| Baseline v3, 2.5 MS/s | 74 delivered, zero skipped/invalid/errors |
| Patched v2, 1.25 and 2.5 MS/s | 74 and 75 delivered respectively; settings restored |
| Installed v3, 1.25 MS/s, 1M blocks | 72/74 delivered; two explicit capacity skips; no invalid visits or terminal error |
| Installed v3, 1.25 MS/s, 500k blocks | 75/75 delivered; 90,000,000 IQ bytes; zero skips/invalid/errors |
| Installed v3, 2.5 MS/s, 1M blocks | 74/74 delivered; zero skips/invalid/errors |
| Installed DMA failure before first IQ | Failed terminal, `EIO`, restored flag; bounded response; subsequent ordinary capture succeeds |
| Installed client cancellation after three visits | Bounded client error; settings restored; subsequent ordinary capture succeeds |
| Installed READSCAN without OPENM | `EBADF` in about 1.3 ms |
| Installed unsupported v3 8 MS/s setup | `EBADMSG` in about 1.1 ms; settings unchanged; ordinary capture succeeds |

The 500k low-rate run recorded 55 feedback acknowledgements, maximum target
revisit 2,965.524 ms (below 3,000 ms), and maximum recall duration 0.3544 ms
(below the 20 ms transition budget). Both receivers contain nonzero noise IQ.
Two counter/host-time anchors were retained with a valid Chrony observation.
The kernel's snapshot-age bound remains explicitly unknown, as in the existing
ABI; no stronger absolute UTC bound is claimed.

The capacity skips with 1M low-rate blocks are real, reported queue pressure,
not missing or mislabeled IQ. A 1M block lasts 800 ms at 1.25 MS/s; conservative
per-visit DMA reservations can exhaust the 16-block queue. The 500k geometry
restores the control's 400 ms block duration and passed with no skips.

All hardware capture attempts share one durable ledger and reserve 1,140 seconds
of the 1,800-second budget. They are RX-only. No other radio was modified.

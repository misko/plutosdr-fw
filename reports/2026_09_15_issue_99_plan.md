## Evidence credited and its limits

The exact candidate FIT is 13,008,423 bytes, SHA-256
`c08feb750cc7c13729d2209f20a2515ef266ea0d04e3a79c8fd5ed4aa938d968`.
It was RAM-booted on the bound PlutoPlus Z7010/512 MiB, JEDEC `ef4019` target.
Linux reported `verified-ear-v1`; its complete 32 MiB read matched the independent
SD baseline. The observed NOR path is `spi2.0`; UID is binary, so future probes
must not assume `spi0.0` or text UID encoding.

The two 64 KiB scratch sectors begin at `0x00ff0000` and `0x01000000`.
Independent SD full-image comparison plus native four-byte endpoint checks
confirmed placement. Saved original sectors reconstruct the entire baseline,
proving unchanged bytes outside the planned sectors. Restoration was checked by
Linux and again independently after full power removal. The final QSPI return
runs the recovered GLRT firmware, not the persistent #99 candidate.

Retained baseline and expected-pattern image bytes were rehashed during this

## Ordered remaining work

1. **Finish PPU integration.** Bring the tested BusyBox backup fix onto current
   main. Define a reviewed writer contract covering the new wrapper, actual
   updater helper, range helper and executable dependencies. Bind those hashes
   into observation and revalidation; do not allowlist the wrapper alone. Test
   altered/missing helpers, changed observations and a second update after
   bootstrap. Retain legacy support and physical `0x01000000` limits.

2. **Close the bounded driver coverage gaps on the same bench.** Reuse the known
   recovery path and establish the unchanged baseline before mutation. Exercise
   a single MTD request spanning 16 MiB, page edges, repeated high-to-low reads
   and writes, and applicable reset/bank-zero behavior. Separate adjacent-sector
   operations do not execute the same split loop as one crossing request.
   Retain host fault-injection coverage; perform hardware fault tests only with
   a defined observable injection and recovery procedure. Each scratch plan must
   identify saved bytes, expected intermediate images, restoration and independent
   physical comparison. Do not repeat the already completed experiment without
   a new coverage objective.

3. **Qualify the boot path separately.** Identify installed QSPI and SD U-Boot
   artifacts independently of the rebuilt candidate. Exercise the active bank
   implementation, actual `read_sf`, full 30 MiB fallback, FIT verification,
   environment save, and reset/handoff. A restored short GLRT FIT boot does not
   establish these paths for an extended image. Install a repaired bootloader
   only if needed, through a separately reviewed recovery transaction. Keep
   persistent DFU unsupported until its own writer path is qualified.

4. **Test the complete conservative persistent transaction.** With PPU integration
   ready, stage the exact below-boundary bootstrap, retain host backups, invoke
   the old writer only within its allowed footprint, and verify written FIT,
   protected regions and the intended environment delta. Record normal candidate
   init/services, warm reboot and actual power-off cold boot. Re-attest the new
   writer, perform a subsequent PPU update, and demonstrate rollback. The bench
   RAM boot used `rdinit=/bin/sh`; it did not exercise these normal-init/update
   paths. Preserve the intended radio runtime explicitly when selecting artifacts.

5. **Test a real crossing FIT through a controlled bench route.** First specify
   the exact writer, image, erase footprint, bootloader and rollback plan. The
   ordinary updater and packager correctly reject this image today; do not
   weaken their global limit to run the experiment. Verify independent physical
   placement, protected regions, warm/cold boot, services and complete rollback.
   Bind any bench-only authorization to the exact target, artifacts and operation.

6. **Promote only the scope actually qualified.** Repeat the required matrix on
   the second Winbond sample/revision and every proposed hardware combination.
   Review a shared PPU/device qualification schema binding hardware identity,
   geometry, running writer, installed bootloader and evidence. Missing matches
   retain the conservative limit. Advance release/source manifests and CI only
   for the resulting tested scope; the draft candidate is not an extended release.

## Completion criteria

Issue #99 remains open until persistent update and boot paths pass the applicable
matrix, rejected requests produce no mutation, independent reads prove physical
placement and protected-region preservation, and rollback/cold-boot evidence is
bound to the shipped artifacts. The completed first-target scratch experiment is
a substantial driver milestone, not a production permission to use all 32 MiB.
